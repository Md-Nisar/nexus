### User Story
As the team building the tenant-admin Access Management console (US-020),
I want every missing API, frontend foundation, test fixture and product decision the console depends on to be in place first,
So that US-020 can be built as a pure UI story on a correct, tested platform, without discovering blockers mid-sprint or shipping a UI that disagrees with the server's authorization rules.

### Background / Context
US-020 is the tenant-admin UI for roles, permissions and role assignment. It was first drafted as one story (US-019, 2026-10-05). A gap review of that draft against the code at `9820d4e` found work that a UI story cannot absorb:
- missing backend endpoints;
- a confirmed defect in the frontend permission guard;
- missing design-system wrappers;
- no app shell;
- no test personas;
- several open product and security decisions.

This story collects those gaps so they can be planned, estimated and closed before US-020 starts. US-020 lists each one as a dependency.

**Scope decision (resolved 2026-10-05).** The role-management UI is part of EPIC-002, not Epic 3, by product-owner decision. This reverses the EPIC-002 [PM] scope boundary and closes EPIC-002 Open Decision #10. Epic 3 keeps tenant creation, tenant settings, and user provisioning and invites.

**How to read the gap register.** Each criterion below names its **evidence** (where the gap was found) so Gate 1 can verify it independently. "Blocks" says which US-020 criteria cannot be built without it.

### Technical Notes (ARC)
- **A1 recommended fix:** option (b), with `authGuard` on the A2 shell's parent route and `permissionGuard` on child routes. It needs no new async plumbing, is enforced by the existing contract spec (tightened to reject same-array composition), and uses the router's documented per-level sequencing. If option (a) is chosen instead, the guard must not trigger a second `refresh()`; it reuses `AuthService`'s in-flight refresh observable.
- **B1/B2/B4** live in the `identity` context (hexagonal layout). They follow US-018 A8: `@RequiresPermission` or `@PublicEndpoint`; B4 uses an authenticated-only annotation as agreed for A8. Paging uses the `PageMetadata`/`PageLinks` shape planned in US-018 C2, shared rather than duplicated. No migration is needed: `idx_users_tenant_id_status` covers tenant + status paging.
- **B4** reuses `UserRoleQueryPort.findActivePermissionNames` and the admin predicate already used by `RoleAssignmentService`. It must not re-implement admin-equivalence.
- **B5/B6** are additive fields on existing DTOs. They are non-breaking; existing `RoleResponse`/`PermissionResponse` contract tests are extended.
- **B8** writes audit rows in the same transaction as the change, consistent with US-018 A6 (ADR-0024, proposed).
- **A3/A4** follow ADR 0004: only `shared/ui` imports `@angular/material`/CDK, there are no raw hex or px values, and each wrapper keeps Material's ARIA contract.
- **Gates:**
  - Frontend: `npm run test:ci`, `npm run lint && npm run format:check`, Playwright + axe.
  - Backend: `./mvnw verify` (B1/B3/B4/B8 add `*IT`s).
- **Feature flags:**
  - `feature.nexus-us019-user-directory.enabled` (B1/B2/B4), default `false`, enabled in `dev`/`test`.
  - B3/B5/B6/B8 sit under the existing US-015 flag.
